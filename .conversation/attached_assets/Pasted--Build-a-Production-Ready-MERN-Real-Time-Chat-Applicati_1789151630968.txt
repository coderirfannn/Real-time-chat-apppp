You are an expert full-stack engineer. Build a complete, production-quality real-time chat application from scratch using the MERN stack.

# 4. REAL-TIME COMMUNICATION

Use Socket.IO.

This is extremely important.

Messages must appear instantly without refreshing the page.

Implement:

### Real-time message sending

When User A sends a message:

1. Frontend sends message through Socket.IO/API.
2. Backend validates the message.
3. Backend saves the message to MongoDB.
4. Backend emits the message to User B if connected.
5. User B sees the message immediately.
6. User A receives confirmation that the message was successfully stored.

Do NOT rely only on frontend state.

MongoDB must remain the source of truth.

# 6. ONLINE / OFFLINE PRESENCE

Implement a reliable presence system.

Every user should have:

* Online
* Offline
* Last seen

When a user connects through Socket.IO:

Set:

isOnline = true

When the socket disconnects:

Set:

isOnline = false

Update:

lastSeen = current timestamp

IMPORTANT:

A user can have multiple browser tabs/devices.

Do NOT mark the user offline simply because one socket disconnected.

Track active socket connections per user.

Only mark the user offline when their last active socket disconnects.

Use an appropriate server-side in-memory connection tracker.

Design the system so Redis can replace the in-memory tracker later for horizontal scaling.

# 9. READ RECEIPTS

When a user opens a conversation:

Mark appropriate unread messages as read.

Emit a Socket.IO event to the sender.

The sender should immediately see the message change from:

✓✓

to the read state.

Store the necessary read information in MongoDB.

Do not mark messages as read merely because they arrived.

They should become read when the recipient actually views the conversation.

---

# 10. OFFLINE MESSAGE HANDLING

This is a critical requirement.

If User A sends a message while User B is offline:

1. Save the message to MongoDB.
2. User A sees it as "Sent".
3. Do not pretend it was delivered.
4. When User B comes online:

   * establish Socket.IO connection
   * fetch/synchronize undelivered messages
   * deliver them
   * update delivery status
5. User A should then see the message become "Delivered".

If User B opens the conversation:

Mark the appropriate messages as read.

This must survive page refreshes and browser restarts.
